# 工业质量控制机器人首个试点规格

用途：在采购机器人前，用同一套现场任务和验收标准比较 G1/H2、四足和轮式平台，避免只比较宣传参数。

## 1. 首个业务结果

选择一条真实、可重复的巡检路线，并定义 1–3 个检查点。试点只验证以下闭环：

1. 从起点或充电点启动任务。
2. 自主到达每个检查点并满足位置/朝向容差。
3. 在检查点采集一种已确认的数据：可见光、热成像或声学。
4. 将带时间、检查点和任务标识的结果传回现有业务系统或结构化文件。
5. 在任务完成、电量门槛、定位失败或网络中断时进入明确的结束/恢复状态。

## 2. 生产与研发双轨

### 生产质检轨道

目标是稳定完成巡检结果，不以“必须是人形”为前提。

- 平坦室内场地、自动充电优先：先评估成熟轮式平台。
- 有门槛、楼梯或非结构化地面：评估四足/轮足平台。
- 只有当人类高度操作、双足通行或操作工具是首个验收要求时，才把人形平台放入生产首选。

### 人形研发轨道

G1 EDU/H2 可单独用于感知、操作、VLA/RL 和人机交互研发，但不让生产巡检的交付时间依赖尚未验证的人形能力。

两条轨道可共享数据格式、任务定义、传感器接口和业务系统输出。

## 3. 采购前必须现场证明

每个候选供应商都在将要交付的准确配置上完成同一测试：

- 主机与扩展计算模块可访问，开发版本/SDK/ROS2 接口明确。
- 相机、热成像、麦克风/声学、IMU、LiDAR、里程计和 TF 提供可用时间戳。
- `cmd_vel` 或等价控制接口的频率、速度/加速度限制和拒绝条件可验证。
- 网络中断、控制进程退出和定位失效时有 watchdog 与确定性停止。
- 从干净系统按文档完成一次部署，不使用供应商预配置演示机掩盖依赖。
- 自动充电包含：返回、末端对准、开始充电、充电确认、任务恢复或安全等待。
- 传感器、电源、安装位和载荷余量针对实际上装确认，不只看本体额定参数。

## 4. 现场输入清单

- 路线平面图、长度、宽度、坡度、门槛、楼梯、门和电梯。
- 地面材质、反光/玻璃、照明变化、粉尘/水汽、温度与防护要求。
- 每个检查点的位置、朝向、允许停留时间与采集对象。
- 可见光/热成像/声学的具体异常定义，以及是否人工复核。
- Wi-Fi/5G/局域网覆盖、离线要求和允许的数据出口。
- 每班运行时长、充电窗口、人工干预允许时间。
- 现有 CMMS、MES、工单、告警或数据存储接口。

## 5. 推荐系统边界

```text
任务/检查点定义
      ↓
业务编排与状态机
      ↓
平台适配器（导航、停止、恢复、充电）
      ↓
机器人本体 + 传感器上装
      ↓
带时间戳的检查结果 → 复核/工单/报告
```

平台适配器必须隔离不同机器人的运动、里程计、充电和故障语义。上层检查任务不直接调用厂商私有动作。

## 6. 试点验收证据

- 连续任务视频，包含启动、路线、检查点、采集、停止/接管和结束状态。
- 每次运行的任务 ID、检查点时间、位姿/状态和结果文件。
- 至少一次网络或定位异常的安全退出记录。
- 自动充电使用场景必须提供完整充电闭环记录。
- 从干净环境部署的命令和依赖清单。
- 已知限制、需要人工处理的条件和不可承诺项。

## 7. 首轮不承诺

- 未测试的 24/7 连续运行、准确率、续航、防爆或 IP 等级。
- 未定义异常标准时的“AI 自动识别所有问题”。
- 未完成安全验证的人机混行、开门/电梯或自主操作设备。
- 把仿真成功、SDK 返回成功或一次 Demo 当作现场稳定性证明。
